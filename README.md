# Гібридна рекомендаційна система цифрового контенту

Дипломний проєкт: «Інформаційна технологія персоналізованого рекомендаційного аналізу цифрового контенту на основі гібридних алгоритмів машинного навчання».

Вебплатформа з каталогом фільмів і книг, яка рекомендує, що подивитися або почитати. Рекомендації будує гібрид класичних ML-алгоритмів (колаборативна фільтрація ALS + контентна схожість на ембедингах BGE-M3), а локальна мовна модель Qwen3 8B (через Ollama) переранжовує кандидатів під конкретного користувача і пояснює кожну рекомендацію людською мовою. Платні API не використовуються — усе працює локально.

Стан: реалізовано всі етапи плану (0–8). Повна специфікація й журнал етапів: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md). Матеріали для пояснювальної записки (таблиці метрик, графіки, знімки екрана, схема архітектури): [docs/materials/](docs/materials/).

## Як це працює

```
оцінки та перегляди користувача
        │
        ├─► ALS (implicit)            → top-200 кандидатів за схожістю поведінки
        ├─► контент (BGE-M3, pgvector) → top-200 кандидатів за схожістю змісту
        │
        ▼
  гібридне злиття оцінок  → top-30
        │
        ▼
  Qwen3 8B (Ollama)       → top-10 + пояснення «чому саме це»
```

1. **Колаборативна фільтрація (ALS).** Матриця «користувач × об'єкт» розкладається на латентні фактори; рекомендуються об'єкти, які вподобали користувачі зі схожою поведінкою.
2. **Контентна модель.** Опис кожного об'єкта (назва, жанри, теги, анотація) перетворюється на вектор BGE-M3 (1024 виміри). Профіль користувача — зважене середнє векторів оцінених ним об'єктів; найближчі вектори шукає pgvector.
3. **Гібрид.** Нормалізовані оцінки двох моделей зливаються з вагою α, яка залежить від кількості оцінок користувача (новачок — більше контенту, досвідчений — більше ALS). Альтернатива — ранговий RRF.
4. **LLM.** Qwen3 отримує профіль смаків і 30 кандидатів, повертає впорядкований top-10 з поясненнями у форматі JSON. Якщо модель недоступна або відповіла некоректно — показується гібридний список без пояснень.

## Зв'язки між сервісами

```
 Браузер
    │ http://localhost:WEB_HOST_PORT
    ▼
┌──────────────┐  /api/* (rewrite)  ┌──────────────┐  SQL :5432   ┌────────────────────┐
│ web (Next.js)│ ─────────────────► │ api (FastAPI)│ ───────────► │ db (Postgres +     │
│ :3000        │                    │ :8000        │              │ pgvector)          │
└──────────────┘                    └──────┬───────┘              └────────────────────┘
                                           │ HTTP :11434
                                           ▼
                                    ┌──────────────┐
                                    │ Ollama (хост)│  qwen3:8b, bge-m3
                                    └──────────────┘
```

- Браузер звертається лише до `web`; запити `/api/*` Next.js проксіює на `api` (без CORS, сесія в httpOnly-cookie). Виняток — публічні зображення обкладинок, які `<img>` бере напряму з CDN TMDB і Open Library.
- `api` — єдиний сервіс, що говорить із базою та з Ollama. До TMDB звертаються лише офлайн-скрипти в контейнері `api`.
- Ollama запускається нативно на Windows (доступ до GPU), контейнер `api` бачить його як `http://host.docker.internal:11434`.
- Навчені моделі ALS і результати оцінювання лежать в іменованому томі `artifacts` (`/app/artifacts`), сирі датасети — у томі `rawdata` (`/app/data`).
- Bind-монтувань теки проєкту немає: Docker Desktop не монтує шляхи, де назва теки довша за 255 байт, а довгі кириличні назви саме такі. Код вшивається в образ, у режимі розробки його синхронізує `docker compose watch`.

## Вимоги

- Windows 10/11 з Docker Desktop (WSL2); Docker-у виділено щонайменше 8 ГБ RAM (імпорт MovieLens 25M).
- [Ollama](https://ollama.com/download) для Windows.
- Відеокарта з 8 ГБ VRAM (рекомендовано). На CPU працює, але ембединги й пояснення рахуються значно довше.
- ~20 ГБ вільного місця (моделі ≈ 6,5 ГБ, датасети ≈ 1,5 ГБ, база, образи).
- Необов'язково: безкоштовний ключ [TMDB](https://www.themoviedb.org/settings/api) для постерів фільмів.

## Запуск з нуля

Команди виконуються з кореня репозиторію. Порти на хості беруться з `.env`
(`WEB_HOST_PORT`, `API_HOST_PORT`, `DB_HOST_PORT`); нижче вжито типові 3000 і 8000.

**1. Моделі Ollama** (один раз):

```bash
ollama pull qwen3:8b
```

```bash
ollama pull bge-m3
```

**2. Налаштування.** Скопіювати шаблон і в `.env` замінити `JWT_SECRET` та `ADMIN_TOKEN`
(для `JWT_SECRET` — щонайменше 32 байти; згенерувати можна `python -c "import secrets; print(secrets.token_urlsafe(48))"`).
Якщо порти 3000/8000/5433 зайняті — змінити `*_HOST_PORT`. Для постерів — вписати `TMDB_API_KEY`
або `TMDB_ACCESS_TOKEN`.

```bash
cp .env.example .env
```

**3. Сервіси й схема БД:**

```bash
docker compose up -d --build
```

```bash
docker compose exec api alembic upgrade head
```

**4. Дані** (MovieLens 25M ≈ 250 МБ і Book-Crossing; імпорт MovieLens — кілька хвилин):

```bash
docker compose exec api python -m scripts.download_data
```

```bash
docker compose exec api python -m scripts.import_movielens
```

```bash
docker compose exec api python -m scripts.import_bookcrossing
```

Необов'язкове збагачення книг анотаціями й тематиками з Open Library (≈ 720 запитів з паузою,
відповіді кешуються на диску; повторний запуск продовжує роботу):

```bash
docker compose exec api python -m scripts.enrich_openlibrary
```

**5. Ембединги BGE-M3** для всього каталогу (≈ 54 тис. об'єктів; на GPU 8 ГБ — порядку години):

```bash
docker compose exec api python -m scripts.build_embeddings
```

**6. Обкладинки:** постери фільмів із TMDB (потрібен ключ) і обкладинки книг з Open Library за ISBN:

```bash
docker compose exec api python -m scripts.fetch_covers
```

**7. Навчання ALS і перезапуск API**, щоб моделі завантажилися в пам'ять:

```bash
docker compose exec api python -m scripts.train_als
```

```bash
docker compose restart api
```

**8. Готово.** Відкрити http://localhost:3000: каталог доступний гостям, після реєстрації —
онбординг, рекомендації з поясненнями й профіль. Стан компонентів (БД, Ollama, моделі, ALS) —
на сторінці `/status`, результати експериментів — на `/evaluation` (після кроку 9).
Документація API: http://localhost:8000/docs.

**9. Наукове оцінювання** (необов'язково для роботи сайту; повний прогін ≈ година на домен):

```bash
docker compose exec api python -m scripts.evaluate --domain all
```

## Скрипти даних і моделей

**Імпорт.** Скрипти можна запускати повторно: імпорт оновлює записи за зовнішніми ID, не дублюючи
їх, і виконується в одній транзакції. Для вже розпакованих файлів є `--input-dir`
(шлях усередині контейнера).

**Ембединги.** `build_embeddings` обробляє лише відсутні вектори, пакетами по 32, і зберігає кожен
пакет окремо; повторний запуск продовжує роботу після переривання, тимчасові помилки Ollama
повторюються з паузою. Параметри: `--domain movie|book`, `--batch-size 1..32`, `--limit N`.
Після заповнення всього каталогу скрипт створює HNSW-індекс і оновлює статистику БД.
Зміна назви, року, авторів, жанрів, опису, тегів або видавця скидає застарілий вектор
через тригер БД — після збагачення знову запустіть цей скрипт.

**TMDB.** Ключі налаштовуються лише на backend: `TMDB_API_KEY` — короткий ключ API,
`TMDB_ACCESS_TOKEN` — довгий токен доступу. Можна задати обидва: клієнт використовує
`Authorization: Bearer`, а за порожнього токена — ключ у параметрі `api_key`. Після зміни `.env`
контейнер треба перестворити (`docker compose up -d api`; звичайний restart не оновлює змінні
середовища). Перевірка без друку секретів і без змін у каталозі:

```bash
docker compose exec api python -m scripts.check_tmdb --auth both
```

Є також `--auth key`, `--auth token`, `--auth auto` (типово). `fetch_covers` ідемпотентний:
фільми без постера в TMDB позначаються перевіреними й повторно не запитуються.
Параметри: `--domain movie|book`, `--limit N`, `--workers N`. Якщо обкладинки немає,
інтерфейс показує типографічну заглушку.

**ALS.** `train_als` має параметри `--domain movie|book|all`, `--factors`, `--regularization`,
`--iterations`, `--num-threads`, `--output-dir`. За замовчуванням: 64 фактори, регуляризація 0.05,
20 ітерацій, 4 CPU-потоки, `seed=42`; потоки BLAS обмежено до 1. Файли `als_movie.npz`,
`als_movie_maps.json`, `als_book.npz`, `als_book_maps.json` зберігаються в томі `artifacts`
і читаються під час запуску API. Ці артефакти навчені на всіх даних для вебзастосунку;
оцінювання навчає власні моделі лише на навчальній частині.

Перезавантаження без рестарту: `POST /api/admin/reload-models` через Next.js із заголовком
`X-Admin-Token` (значення `ADMIN_TOKEN` з `.env`; порожнє або `change-me` вимкнено).
Відповідь: `{"loaded":{"movie":true,"book":true}}`. Некоректний токен дає 401, відсутні або
пошкоджені артефакти — 503; уже завантажені робочі моделі залишаються в пам'яті.

**Моделі.** У `app/recsys/` доступні ALS, контентна модель, популярність, зважений гібрид і RRF.
Для нового користувача ALS обчислює фактор за його оцінками без перенавчання. Гібрид отримує
до 200 кандидатів від кожної моделі, нормалізує оцінки й адаптує вагу ALS до кількості позитивних
оцінок; за порожньої історії використовує популярне.

## API

Публічний API доступний через Next.js з префіксом `/api`:

- `GET /api/items?domain=movie&q=Matrix&sort=popular&page=1&page_size=24` — каталог,
  пошук за буквальним фрагментом назви, `genre`, сортування `popular|rating|year`;
- `GET /api/items/genres?domain=movie` — жанри з кількістю об'єктів;
- `GET /api/items/{id}` — метадані й опис;
- `GET /api/items/{id}/similar` — до 12 схожих об'єктів того самого домену;
- `GET /api/evaluation/results` — зведені результати оцінювання для обох доменів;
- `GET /api/evaluation/files/{name}` — графіки PNG і таблиці CSV звіту (лише за білим списком імен).

Каталог повертає `{items, total, page, page_size}`, схожі об'єкти — список
`{item, score}` з косинусною схожістю у межах −1…1. Вектори API не повертає.
Якщо вектор ще не побудовано, список схожого порожній. Детальна картка публічна:
для гостя `my_rating=null`, для авторизованого користувача — його оцінка;
відкриття картки з коректною сесією додає запис у персональну історію переглядів.

Користувацький API (усі шляхи через Next.js мають префікс `/api`):

- `POST /auth/register`: JSON `{email, password, display_name}`; створює користувача
  й повертає профіль зі статусом 201. Пароль — 8–128 символів, ім'я — 1–80.
- `POST /auth/login`: `{email, password}`; `POST /auth/logout` видаляє cookie поточного браузера.
- `GET /auth/me`: профіль і `rating_counts` окремо для фільмів та книг.
- `PUT /ratings/{item_id}`: `{value: 1..10}` — ціле число, створення або зміна оцінки;
  `DELETE /ratings/{item_id}` — видалення власної оцінки (204, також при повторному виклику).
- `GET /me/ratings`, `GET /me/history`: власні оцінки та перегляди; необов'язковий `domain`,
  `page≥1`, `page_size=24` за замовчуванням, максимум 100.
- `GET /onboarding/items?domain=movie&k=20`: до 50 популярних невідомих користувачу
  об'єктів із різних жанрів для початкового оцінювання.
- `GET /recommendations?domain=movie&model=hybrid&k=10`: до 50 персональних результатів;
  моделі `hybrid`, `als`, `content`, `popular`.
- `POST /recommendations/explain`: `{"domain":"movie"}` — переранжування й пояснення Qwen3.

Реєстрація та вхід установлюють JWT у cookie `session` на 7 днів: `HttpOnly`,
`SameSite=Lax`, `Path=/`. `JWT_SECRET` має містити щонайменше 32 байти;
типове `change-me` не приймається. Для HTTPS задайте `SESSION_COOKIE_SECURE=true`
(локально через HTTP — `false`). Email нормалізується до нижнього регістру,
паролі зберігаються як Argon2id-хеші. Захищені ендпоінти без коректної сесії дають 401;
повторна реєстрація адреси — 409. Історія та оцінки інших користувачів не повертаються.

Рекомендації повертають список `{item, score, sources: {als, content, popular}, explanation}`.
Оцінки нормалізовано до [0,1] у пулі кандидатів (до 200 для кожної моделі).
Для порожньої історії гібрид показує популярне; чиста контентна модель та ALS
можуть повернути порожній список, якщо немає потрібного сигналу. Якщо явно обрано
ALS, але модель не завантажена, відповідь — 503; гібрид працює з доступними джерелами.

Без кешу `explanation=null`. `POST /recommendations/explain` з чинною cookie-сесією:
Qwen3 обирає до 10 із 30 гібридних кандидатів і пояснює вибір українською. Усі номери,
дублікати та тексти перевіряються; неповний список доповнюється гібридними рекомендаціями
без пояснень. За таймауту чи недоступної моделі відповідь також 200 із гібридним списком.
Невдалі генерації без жодного пояснення не кешуються, тому наступний виклик може відновити пояснення.

Повторний POST використовує `llm_cache`; звичайний GET для `model=hybrid` теж
читає цей кеш і не викликає Ollama. Для інших моделей пояснення не додаються.
При `k>10` після переранжованої десятки йдуть решта гібридних кандидатів без повторів.
Порядок після LLM може відрізнятися від сортування за `score`: числові оцінки та
внески моделей зберігаються, Qwen3 змінює лише порядок і пояснення.

Ключ кешу враховує оцінки з часом змін, перегляди, кандидатів і метадані,
версію промпту та назву моделі. Оновлення оцінки й новий перегляд очищують кеш
відповідного домену. Якщо історія змінилася під час генерації, старі пояснення
не записуються; повертається актуальний гібридний список. Запити одного користувача
й домену об'єднуються очікуванням у межах одного процесу API.

Генерація має загальний бюджет 120 с, проксі Next.js налаштовано на 130 с.
Читання БД завершується перед очікуванням моделі. У промпт не потрапляють email,
пароль, cookie чи ID бази; передаються номери кандидатів і метадані смаків.
Пояснення спираються на явні факти: спільний жанр/автора або схожу назву;
для відсутньої історії не вигадуються вподобання.

## Дані

| Джерело | Що беремо | Примітка |
|---|---|---|
| [MovieLens](https://grouplens.org/datasets/movielens/) | `ml-25m`: 18 430 фільмів (≥ 20 оцінок), 25 000 користувачів, 3,85 млн оцінок | оцінки 0.5–5, є часові мітки, жанри, теги |
| [Book-Crossing](https://grouplens.org/datasets/book-crossing/) | 36 002 книги (≥ 5 взаємодій), 15 222 користувачі, 564 тис. взаємодій | оцінки 1–10, 0 = неявна взаємодія; часових міток немає |
| [Open Library](https://openlibrary.org/developers/api) | анотації, тематики, обкладинки | збагачення лише відфільтрованих книг, з кешем |
| [TMDB](https://www.themoviedb.org/) | постери фільмів | потрібен безкоштовний ключ у `.env` |

Датасети завантажуються скриптом у том `rawdata` і в репозиторій не потрапляють.
Оцінки MovieLens переводяться в єдину шкалу 1–10 (×2).

Офіційний сервер Book-Crossing недоступний. За замовчуванням `download_data`
бере сирі `BX-*.csv.gz` з [копії zheng-da/BookCrossing](https://github.com/zheng-da/BookCrossing/tree/b21eb595d30bb0a9cda840be937af02b9b7bfa77),
зафіксованої на коміті `b21eb595d30bb0a9cda840be937af02b9b7bfa77`.
Виправлені файли та готові навчальні/тестові підвибірки з цього репозиторію не використовуються.
Походження файлів записується в `*.source.json` у томі даних.
Оригінальний `BX-CSV-Dump.zip`, якщо він є, можна скопіювати в `/app/data/`:
тоді скрипт використає його. Інший URL архіву задається через `--bookcrossing-url`;
повернення до старого джерела — через `--bookcrossing-source official`.

MovieLens за замовчуванням — `ml-25m`. Каталог складають фільми з ≥ 20 оцінками в усьому наборі
(`--min-movie-ratings`). Оцінки беруться від випадкової вибірки користувачів
(`--max-users 25000`, `seed=42`; `0` — усі), щоб навчання й оцінювання вміщалися в пам'ять.
Для швидкої розробки `download_data` й `import_movielens` приймають
`--variant ml-latest-small` (≈ 9,7 тис. фільмів) або `ml-1m`.
ID користувачів між варіантами не узгоджені, тому імпорт іншого варіанта потребує
`--replace`: він замінює користувачів і оцінки MovieLens, а фільми з тим самим `movieId`
зберігають ембединги й постери.

Book-Crossing проходить повторну k-core-фільтрацію: ≥ 5 взаємодій на користувача (`--min-user`) й
≥ 5 на книгу (`--min-book`). Неявна оцінка `0` зберігається як `implicit=true, value=NULL`.
`rating_count` враховує всі взаємодії, `rating_avg` — лише явні оцінки у шкалі 1–10.

## Наукова частина

Порівнюються моделі: популярність (базова лінія), контентна (BGE-M3), колаборативна (ALS),
гібрид (зважений і RRF) та гібрид + переранжування Qwen3. Метрики: Precision@K, Recall@K, NDCG@K
для K ∈ {5, 10, 20}, покриття каталогу, окремо — холодний старт (природний і імітований).
MovieLens розбивається за часом, Book-Crossing — випадково (`seed=42`); гіперпараметри
підбираються за NDCG@10 на валідації, ALS для експериментів навчається лише на навчальній частині.

Основні результати (NDCG@10 на тесті):

| Модель | MovieLens | Book-Crossing |
|---|---|---|
| Популярність | 0.0498 | 0.0083 |
| Контентна (BGE-M3) | 0.0241 | 0.0262 |
| ALS | 0.0934 | 0.0508 |
| Зважений гібрид | **0.0962** | **0.0549** |
| RRF | 0.0798 | 0.0518 |

Повні таблиці, холодний старт, ефект Qwen3 і висновки — у [docs/materials/](docs/materials/),
на сторінці `/evaluation` і в розділі 10 [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).

```bash
docker compose exec api python -m scripts.evaluate --domain movie
```

```bash
docker compose exec api python -m scripts.evaluate --domain book
```

Повний прогін (сітка 18 × 12 конфігурацій і 200 користувачів через Qwen3 на домен) триває
близько години; відповіді LLM кешуються на диску, тож повторний запуск значно швидший.
Для швидкої перевірки: `--grid small --skip-llm --max-users 300`. Ключ `--redraw` лише перемальовує
графіки з останнього звіту, без обчислень.

Результати зберігаються в томі `artifacts` (`/app/artifacts/eval/`: CSV, JSON, графіки PNG)
і відображаються на сторінці `/evaluation`. Скопіювати на диск:

```bash
docker compose cp api:/app/artifacts/eval ./eval-results
```
