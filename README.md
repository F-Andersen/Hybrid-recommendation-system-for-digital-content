# Гібридна рекомендаційна система цифрового контенту

Дипломний проєкт: «Інформаційна технологія персоналізованого рекомендаційного аналізу цифрового контенту на основі гібридних алгоритмів машинного навчання».

Вебплатформа з каталогом фільмів і книг, яка рекомендує, що подивитися або почитати. Рекомендації будує гібрид класичних ML-алгоритмів (колаборативна фільтрація ALS + контентна схожість на ембедингах BGE-M3), а локальна мовна модель Qwen3 8B (через Ollama) переранжовує кандидатів під конкретного користувача і пояснює кожну рекомендацію людською мовою. Платні API не використовуються — усе працює локально.

Повна специфікація для реалізації: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).

## Як це працює

```
оцінки та перегляди користувача
        │
        ├─► ALS (implicit)            → top-200 кандидатів за схожістю поведінки
        ├─► контент (BGE-M3, pgvector) → top-200 кандидатів за схожістю змісту
        │
        ▼
  гібридне злиття оцінок  → top-30
        │
        ▼
  Qwen3 8B (Ollama)       → top-10 + пояснення «чому саме це»
```

1. **Колаборативна фільтрація (ALS).** Матриця «користувач × об'єкт» розкладається на латентні фактори; рекомендуються об'єкти, які вподобали користувачі зі схожою поведінкою.
2. **Контентна модель.** Опис кожного об'єкта (назва, жанри, теги, анотація) перетворюється на вектор BGE-M3 (1024 виміри). Профіль користувача — зважене середнє векторів оцінених ним об'єктів; найближчі вектори шукає pgvector.
3. **Гібрид.** Нормалізовані оцінки двох моделей зливаються з вагою α, яка залежить від кількості оцінок користувача (новачок — більше контенту, досвідчений — більше ALS).
4. **LLM.** Qwen3 отримує профіль смаків і 30 кандидатів, повертає впорядкований top-10 з поясненнями у форматі JSON. Якщо модель недоступна або відповіла некоректно — показується гібридний список без пояснень.

## Зв'язки між сервісами

```
 Браузер
    │ http://localhost:3000
    ▼
┌──────────────┐  /api/* (rewrite)  ┌──────────────┐  SQL :5432   ┌────────────────────┐
│ web (Next.js)│ ─────────────────► │ api (FastAPI)│ ───────────► │ db (Postgres +     │
│ :3000        │                    │ :8000        │              │ pgvector)          │
└──────────────┘                    └──────┬───────┘              └────────────────────┘
                                           │ HTTP :11434
                                           ▼
                                    ┌──────────────┐
                                    │ Ollama (хост)│  qwen3:8b, bge-m3
                                    └──────────────┘
```

- Браузер звертається лише до `web`; запити `/api/*` Next.js проксіює на `api` (без CORS, сесія в httpOnly-cookie).
- `api` — єдиний сервіс, що говорить із базою та з Ollama.
- Ollama запускається нативно на Windows (доступ до GPU), контейнер `api` бачить його як `http://host.docker.internal:11434`.
- Навчені моделі ALS лежать в іменованому томі `artifacts` (`/app/artifacts` у контейнері) і завантажуються в пам'ять `api` під час старту. Сирі датасети — у томі `rawdata` (`/app/data`).
- Bind-монтувань теки проєкту немає: Docker Desktop не монтує шляхи, де назва теки довша за 255 байт, а довгі кириличні назви саме такі. Код вшивається в образ, у режимі розробки його синхронізує `docker compose watch`.

## Вимоги

- Windows 10/11 з Docker Desktop (WSL2).
- [Ollama](https://ollama.com/download) для Windows.
- Відеокарта з 8 ГБ VRAM (рекомендовано). На CPU працює, але пояснення генеруються повільно (десятки секунд).
- ~15 ГБ вільного місця (моделі ≈ 6,5 ГБ, дані, образи).

Стан реалізації: каркас, дані, моделі рекомендацій, каталог, реєстрація, оцінки,
історія та персональні рекомендації через API (етапи 0–4).

```bash
docker compose exec api alembic upgrade head
```

```bash
docker compose exec api pytest
```

```bash
docker compose exec api ruff check .
```

```bash
docker compose exec api python -m scripts.download_data
```

```bash
docker compose exec api python -m scripts.import_movielens
```

```bash
docker compose exec api python -m scripts.import_bookcrossing
```

```bash
docker compose exec api python -m scripts.enrich_openlibrary
```

Побудувати ембединги всього каталогу через локальний BGE-M3:

```bash
docker compose exec api python -m scripts.build_embeddings
```

Скрипт обробляє лише відсутні ембединги, пакетами по 32, і зберігає кожен пакет
окремо. Повторний запуск продовжує роботу після переривання. Є параметри
`--domain movie|book`, `--batch-size 1..32`, `--limit N` для коротких перевірок.
Після заповнення всього каталогу він створює HNSW-індекс і оновлює статистику БД.
Зміна назви, року, авторів, жанрів, опису, тегів або видавця автоматично скидає
застарілий вектор через тригер БД — після збагачення знову запустіть цей скрипт.

Відкрити http://localhost:3000 (головна сторінка показує стан усіх компонентів). Документація API: http://localhost:8000/docs. Порти — з `WEB_HOST_PORT` і `API_HOST_PORT`.

Навчити ALS для обох доменів на всіх поточних оцінках:

```bash
docker compose exec api python -m scripts.train_als
```

Скрипт має параметри `--domain movie|book|all`, `--factors`, `--regularization`,
`--iterations`, `--num-threads`, `--output-dir`. За замовчуванням: 64 фактори,
регуляризація 0.05, 20 ітерацій, 4 CPU-потоки, `seed=42`; потоки BLAS обмежено до 1.
Файли `als_movie.npz`, `als_movie_maps.json`, `als_book.npz`, `als_book_maps.json`
зберігаються в томі `artifacts`. У них є фактори, матриця позитивних взаємодій,
відображення ID та параметри. Моделі автоматично читаються під час запуску API:

```bash
docker compose restart api
```

Для перезавантаження без рестарту виконайте `POST /api/admin/reload-models`
через Next.js із заголовком `X-Admin-Token`, значення якого береться з `ADMIN_TOKEN`
у `.env`. Порожній або стандартний `change-me` вимкнено. Відповідь:
`{"loaded":{"movie":true,"book":true}}`. Некоректний токен дає 401, відсутні або
пошкоджені артефакти — 503; уже завантажені робочі моделі залишаються в пам'яті.

У `app/recsys/` доступні ALS, контентна модель, популярність, зважений гібрид
і RRF. Для нового користувача ALS обчислює фактор за його оцінками без перенавчання.
Гібрид отримує до 200 кандидатів від кожної моделі, нормалізує оцінки й адаптує
вагу ALS до кількості позитивних оцінок; за порожньої історії використовує популярне.
Користувацький ендпоінт `/recommendations` використовує ці моделі з поточною історією користувача.

Ці артефакти навчені на всіх даних для вебзастосунку. Для наукових експериментів
етапу 7 потрібне окреме навчання на навчальній частині та інший каталог артефактів.

Скрипти даних можна запускати повторно: імпорт оновлює записи за зовнішніми ID,
не дублюючи їх, а Open Library використовує дисковий кеш. Кожен імпорт виконується
в одній транзакції; збагачення зберігає результат після кожного пакета з 50 книг.
Для короткої перевірки мережі: `python -m scripts.enrich_openlibrary --limit 50`
усередині контейнера `api`.

Публічний API доступний через Next.js з префіксом `/api`:

- `GET /api/items?domain=movie&q=Matrix&sort=popular&page=1&page_size=24` — каталог,
  пошук за буквальним фрагментом назви, `genre`, сортування `popular|rating|year`;
- `GET /api/items/genres?domain=movie` — жанри з кількістю об'єктів;
- `GET /api/items/{id}` — метадані й опис;
- `GET /api/items/{id}/similar` — до 12 схожих об'єктів того самого домену.

Каталог повертає `{items, total, page, page_size}`, схожі об'єкти — список
`{item, score}` з косинусною схожістю у межах −1…1. Вектори API не повертає.
Якщо вектор ще не побудовано, список схожого порожній. Детальна картка публічна:
для гостя `my_rating=null`, для авторизованого користувача — його оцінка;
відкриття картки з коректною сесією додає запис у персональну історію переглядів.

Користувацький API (усі шляхи через Next.js мають префікс `/api`):

- `POST /auth/register`: JSON `{email, password, display_name}`; створює користувача
  й повертає профіль зі статусом 201. Пароль — 8–128 символів, ім'я — 1–80.
- `POST /auth/login`: `{email, password}`; `POST /auth/logout` видаляє cookie поточного браузера.
- `GET /auth/me`: профіль і `rating_counts` окремо для фільмів та книг.
- `PUT /ratings/{item_id}`: `{value: 1..10}` — ціле число, створення або зміна оцінки;
  `DELETE /ratings/{item_id}` — видалення власної оцінки (204, також при повторному виклику).
- `GET /me/ratings`, `GET /me/history`: власні оцінки та перегляди; необов'язковий `domain`,
  `page≥1`, `page_size=24` за замовчуванням, максимум 100.
- `GET /onboarding/items?domain=movie&k=20`: до 50 популярних невідомих користувачу
  об'єктів із різних жанрів для початкового оцінювання.
- `GET /recommendations?domain=movie&model=hybrid&k=10`: до 50 персональних результатів;
  моделі `hybrid`, `als`, `content`, `popular`.

Реєстрація та вхід установлюють JWT у cookie `session` на 7 днів: `HttpOnly`,
`SameSite=Lax`, `Path=/`. `JWT_SECRET` має містити щонайменше 32 байти;
типове `change-me` не приймається. Для HTTPS задайте `SESSION_COOKIE_SECURE=true`
(локально через HTTP — `false`). Email нормалізується до нижнього регістру,
паролі зберігаються як Argon2id-хеші. Захищені ендпоінти без коректної сесії дають 401;
повторна реєстрація адреси — 409. Історія та оцінки інших користувачів не повертаються.

Рекомендації повертають список `{item, score, sources: {als, content, popular}, explanation}`.
Оцінки нормалізовано до [0,1] у пулі кандидатів (до 200 для кожної моделі).
Для порожньої історії гібрид показує популярне; чиста контентна модель та ALS
можуть повернути порожній список, якщо немає потрібного сигналу. Якщо явно обрано
ALS, але модель не завантажена, відповідь — 503; гібрид працює з доступними джерелами.
`explanation` поки `null`: генерація й читання LLM-кешу додаються на етапі 5.
Оновлення оцінки й новий перегляд очищують кеш пояснень відповідного домену.
Форми входу, профіль та сторінка рекомендацій в інтерфейсі додаються на етапі 6.

## Дані

| Джерело | Що беремо | Примітка |
|---|---|---|
| [MovieLens](https://grouplens.org/datasets/movielens/) | `ml-latest-small` для розробки, `ml-1m` для експериментів | оцінки 0.5–5, є часові мітки, жанри, теги |
| [Book-Crossing](https://grouplens.org/datasets/book-crossing/) | оцінки книг, метадані за ISBN | оцінки 1–10, 0 = неявна взаємодія; часових міток немає |
| [Open Library](https://openlibrary.org/developers/api) | анотації, тематики, обкладинки | збагачення лише відфільтрованих книг, з кешем |

Датасети завантажуються скриптом у том `rawdata` і в репозиторій не потрапляють.

Офіційний сервер Book-Crossing недоступний. За замовчуванням `download_data`
бере сирі `BX-*.csv.gz` з [копії zheng-da/BookCrossing](https://github.com/zheng-da/BookCrossing/tree/b21eb595d30bb0a9cda840be937af02b9b7bfa77),
зафіксованої на коміті `b21eb595d30bb0a9cda840be937af02b9b7bfa77`.
Виправлені файли та готові навчальні/тестові підвибірки з цього репозиторію не використовуються.
Походження файлів записується в `*.source.json` у томі даних.
Оригінальний `BX-CSV-Dump.zip`, якщо він є, можна скопіювати в `/app/data/`:
тоді скрипт використає його. Інший URL архіву задається через `--bookcrossing-url`;
повернення до старого джерела — через `--bookcrossing-source official`.

MovieLens за замовчуванням — `ml-latest-small`. Для експериментів обидва скрипти
`download_data` й `import_movielens` приймають `--variant ml-1m`.
Варіанти потрібно імпортувати в різні бази: ID користувачів між ними не узгоджені,
і скрипт відхиляє спробу змішати їх. Для вже розпакованих файлів імпортери мають
`--input-dir` (шлях усередині контейнера).

Book-Crossing проходить повторну k-core-фільтрацію: ≥ 5 взаємодій на користувача,
≥ 10 на книгу. Неявна оцінка `0` зберігається як `implicit=true, value=NULL`.
`rating_count` враховує всі взаємодії, `rating_avg` — лише явні оцінки у шкалі 1–10.

## Наукова частина

Заплановано на етап 7 (скрипт `evaluate` і сторінка `/evaluation` ще не реалізовані).
Порівнюватимуться моделі: популярність (базова лінія), контентна, колаборативна (ALS), гібридна, гібридна + LLM-переранжування. Метрики: Precision@K, Recall@K, NDCG@K для K ∈ {5, 10, 20}.

```bash
docker compose exec api python -m scripts.evaluate --domain movie
```

```bash
docker compose exec api python -m scripts.evaluate --domain book
```

Результати зберігаються в томі `artifacts` (`/app/artifacts/eval/`: CSV + графіки) і відображаються на сторінці `/evaluation`. Скопіювати на диск для диплома:

```bash
docker compose cp api:/app/artifacts/eval ./eval-results
```
